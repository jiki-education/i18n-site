# Jiki i18n Site - Agent Instructions

Public review site for the Jiki & Exercism Translatathon, served at **i18n.jiki.io**. It
shows each translation next to the English it came from, and publishes each language's
agreed glossary, so native speakers can read both and say what's wrong on the forum.

This site is **disposable**. It exists for the Translatathon (weekend of 31 July - 2 August 2026) and will be deleted afterwards. Deleting it must cost nothing, so keep it that way:
no database, no auth, no user state, no content that exists only here.

## ⚠️ Never hand-edit `src/content/`

Everything under `src/content/` is generated by the **translator** repo
(`../translator`), which is the control panel for all translation work. Editing it here is
always wrong: the next publish silently overwrites your change, and the real source of
truth (the translated files in `../front-end`, and the glossaries in `../translator`) never
learns about it.

Content arrives via, run from `../translator`:

```
./scripts/publish-glossary    <lang|all>
./scripts/publish-translation <lang|all> <type> <slug> [--stub]
```

If content here looks wrong, fix it at source and re-publish. If the _rendering_ is wrong,
that's a bug in this repo and belongs in `src/pages/`, `src/components/`, or `src/lib/`.

The dependency runs one way only: this repo never reads from `../translator`, and nothing
here is ever copied back into it.

## Content model

| Collection     | Path                                               | What it is                                                                                              |
| -------------- | -------------------------------------------------- | ------------------------------------------------------------------------------------------------------- |
| `translations` | `src/content/translations/<lang>/<type>/<slug>.md` | A translated item. `status: planned` is a "coming soon" stub with no body; `status: published` has one. |
| `english`      | `src/content/english/<type>/<slug>.md`             | The English source, **frozen** at the moment a translation was published.                               |
| `glossaries`   | `src/content/glossaries/<lang>.json`               | A language's agreed terms, parsed out of its `glossary.md`.                                             |

Two deliberate choices worth not undoing:

- **The English snapshot is frozen, not fetched.** A reviewer's comment must be anchored to
  the text they actually read. When the source moves on, the translation's `en_md5` stops
  matching the snapshot's and the page shows a staleness warning, rather than the English
  silently changing underneath a published translation.
- **The glossary is the live version.** The pinned forum post links here instead of
  carrying a 100-row table. So a glossary edit in `../translator` must be published and
  deployed promptly, or the forum link shows stale terms.

## Pages

- `/` - the Translatathon pitch (copy from `jiki.io/blog/translatathon`), quick links, and
  the full language list in the right-hand sidebar.
- `/<lang>` - what's translated, what's queued, how to help.
- `/<lang>/glossary` - every agreed term, one anchor per row (`#term-loop`) so a forum
  comment can link a single decision. Family locales (`es-419`, `pt-BR`, `zh-CN`) show
  shared rows badged separately from their own.
- `/<lang>/<type>/<slug>` - the translation side by side with the English, with a
  target-only toggle.

## Commands

```bash
./bin/dev     # install + dev server, the usual entry point
pnpm dev      # http://local.jiki.io:3068
pnpm build    # static output to dist/
pnpm preview  # wrangler dev, serving dist/ the way Cloudflare will
pnpm deploy   # astro build && wrangler deploy (CI does this; rarely run by hand)
```

`local.jiki.io` resolves to `127.0.0.1` via `/etc/hosts`, matching how the other Jiki apps
are served locally.

## Deployment

Push to `main` and GitHub Actions deploys to Cloudflare Workers. The workflow mirrors
`front-end/.github/workflows/deploy.yml` (pnpm action-setup v6, setup-node v6 with
`node-version-file: .nvmrc`, explicit secret validation, then `pnpm run deploy`). Static
assets only, so there is no OpenNext build and no R2 upload step.

Requires `CLOUDFLARE_API_TOKEN` and `CLOUDFLARE_ACCOUNT_ID` as repo secrets.

The publish → announce order matters and is not automated on purpose: **deploy first, then
post to the forum**, or the announcement links 404.

## Styling

Design tokens (purple palette, gray scale, Poppins, Source Code Pro) are copied from the
Jiki app's `app/styles/theme/*.css` into `src/styles/global.css`, and `.textual-content`
mirrors the app's `.ui-textual-content` so a translated body renders here the way it
renders on the product. There is no shared package: if the product's palette moves, update
`global.css` by hand.

Every language page must survive its own script. Content is rendered with `lang` and `dir`
set from `src/lib/languages.ts`, so Arabic, Persian and Urdu lay out right-to-left, and the
font stack falls through to Noto/CJK families that Poppins doesn't cover.

## Scope

Translated content only. The **language guides** (`languages/<lang>/guide.md` in the
translator repo) are deliberately not published: they are internal instructions for how to
translate, not something to review. Glossaries are published because they are the decisions
under review.
